# sound-bgm-modal

BGM 演出のある LP に「音を鳴らしてよいか」を最初に確認するモーダルと、Audio の再生・一時停止・停止を安全に管理するライフサイクルをワンセットで導入するスキル。モーダルの HTML/CSS/開閉 JS は references/modal.md、Audio 管理は references/audio-lifecycle.md にある。

## いつ使うか

- 体験型・没入型 LP（ポップアップストア告知、コラボ企画、世界観重視のブランドサイト）で BGM・環境音を流したいとき
- 既存ページの BGM が「タブを切り替えても鳴り続ける」「ページを閉じたのに鳴っている」等の行儀の悪さを直したいとき

## 前提となる判断基準

### BGM を入れてよいか

- **向いている**: 滞在時間の長い体験型コンテンツ、世界観の没入が目的のページ、店舗・イベント告知
- **向いていない**: 商品一覧・購入導線が主目的の通常のルックブック LP（音はコンバージョンの邪魔になる）。迷ったら入れない
- 入れる場合も**必ずユーザーに選ばせる**（勝手に鳴らさない）。これは礼儀の問題であると同時に技術的制約でもある（下記）

### 自動再生ポリシー（技術的制約）

モダンブラウザは**ユーザージェスチャ（クリック等）を起点としない音声再生をブロック**する。したがって:

- 「ページを開いたら自動で BGM」は実装不可能。**モーダルの「Sound ON」ボタンのクリックを再生起点にする**のがこのスキルの構造
- play() は Promise を返し、拒否されることがある。必ず catch し、失敗してもページ進行（モーダルを閉じる等）は止めない

### 音量・ループ

- volume は **0.5 を既定**とする（フルボリュームは事故。BGM は背景に徹する）
- loop: true でループ再生。曲の切れ目が目立つ音源なら、書き出し時にループ用に編集された音源を支給してもらう

## ライフサイクルの契約（references/audio-lifecycle.md が実装）

| タイミング | 挙動 |
|---|---|
| Sound ON クリック | Audio 生成 → play()。成功・失敗いずれでもモーダルを閉じる |
| Sound OFF クリック | 何も再生せずモーダルを閉じる |
| タブ非表示（visibilitychange） | **一時停止**（停止ではない。復帰時に続きから再開するため） |
| タブ復帰 | ユーザーが ON を選んでいた場合のみ再開（play() 失敗は握りつぶす） |
| ページ離脱（pagehide / beforeunload） | **完全停止 + 解放**（pagehide が本命、beforeunload は旧ブラウザ保険） |

## 導入手順

1. BGM 適否を上の判断基準で確認する（不向きなら提案段階で止める）
2. 音源（mp3 等）を sound/ ディレクトリに配置する。ファイルサイズを確認し、必要なら 128kbps 程度に圧縮する
3. references/modal.md のモーダル HTML を body 直下（コンテンツより後）に追加し、CSS を読み込む
4. references/audio-lifecycle.md の Audio 管理モジュールを追加し、モーダルのボタンと接続する
5. モーダル表示中の背面スクロール固定は scroll-lock スキルと併用する（modal.md 内の body クラスでも最低限は動く）
6. モーダルを閉じた後に始まる演出（ヒーロー入場等）があるなら、モーダルの onHidden コールバックから lp-hero スキルのイベント契約に繋ぐ

## 検品チェックリスト

- [ ] Sound ON で BGM が鳴り、音量が控えめ（0.5）でループする
- [ ] Sound OFF でも全ての演出・機能が音無しで完走する
- [ ] タブを切り替えると一時停止し、戻ると続きから再開する（ON を選んだ場合のみ）
- [ ] ページを閉じる・別ページへ遷移・ブラウザバックで音が完全に止まる
- [ ] iOS Safari 実機でモーダルのフェードアウトが正しく再生される（リフロー強制ハックの確認）
- [ ] モーダル表示中、背面のコンテンツが操作・スクロールできない
- [ ] ボタン連打で音が二重再生されない（初期化中フラグの確認）
- [ ] play() がブロックされた場合（コンソール警告のみで）ページ進行が止まらない
