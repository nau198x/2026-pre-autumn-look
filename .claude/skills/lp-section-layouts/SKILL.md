# lp-section-layouts

写真ブロックのレイアウトを、案件規模とレイアウトバリエーション数に応じて 3 方式から選んで導入するスキル。方式ごとの完全コードと HTML 例は references にある。

## いつ使うか

- LP に写真主体のセクション（ルック・ギャラリー・コンテンツブロック）を追加するとき
- 既存の写真ブロックの並び・幅・比率を変更するとき
- レイアウト定義がブロック固有の上書きで散らかってきて整理したいとき

## 変種（方式）の判断基準

| 方式 | 特徴 | 向いている条件 | 参照 |
|---|---|---|---|
| a: ユーティリティ型 | 汎用クラスの合成で多数の組合せを表現 | ブロック数が多い（10+）/ 幅・列数・比率の組合せが多様 / 制作中に構成変更が頻発する | references/utility-system.md |
| b: 名前付きパターン型 | 完成形パターンを 3〜4 個定義して反復 | レイアウトが少数固定 / ページ全体を同じリズムで反復させたい / 統一感最優先 | references/named-patterns.md |
| c: grid-area コラージュ型 | grid-template-areas の語彙で変則配置を命名 | 雑誌的コラージュ（中央 1 枚+周囲、モザイク、挟み込み）/ PC と SP で配置が大きく入れ替わる | references/collage-grid.md |

### 判断の観点

- まず「デザインカンプに現れるレイアウトの種類数」を数える。3〜4 種の反復で全ページが説明できるなら b、「幅 × 列数 × 比率」の直交する組合せで説明できるなら a、行をまたぐ変則配置（中央挟み込み・モザイク）があるなら c
- 混在も可（基本は a か b、変則ブロックのみ c を併用）。ただし同一セクション内で方式を混ぜない
- 迷ったら b。パターンが 5 種を超えて増殖し始めたら a への移行を検討する

### 命名規約

- 方式 a: 機能名クラスのみ（.layout-*, .w-*, .gap-*, .ratio-*）。ブロック固有の ID はアンカー・JS フック用途に限定する
- 方式 b / c: BEM。ルートは .look、パターンはモディファイア（.look--pattern-a, .look__item--grid-duo）、要素は .look__image / .look__credits 等
- 新パターン名は見た目の形容ではなく構成の説明にする（例: 中央 1 枚を上下 2 枚組で挟む → --sandwich-duo）

### 劣化防止ルール（厳守）

実案件で、方式 a の体系にブロック固有 ID の上書き（#photo-block-1〜21 個別指定）が積み重なり数百行に膨張した劣化実例がある。references/utility-system.md 末尾のアンチパターン解説を必ず読み、以下を守る。

- ID セレクタでレイアウトを上書きしない
- 同じ調整が 2 ブロックで必要になった時点でモディファイアクラスへ昇格する（昇格手順は references/utility-system.md に記載）
- 真にワンオフの例外は CSS 末尾の「例外」セクションに隔離し、理由をコメントで残す。例外がファイルの 1 割を超えたら方式選定から見直す

## 導入手順

1. 上の判断表で方式を決め、該当する references を読む
2. デザイントークン（--spacing-*, --color-*, --content-width-*）が :root に定義済みか確認する。無ければ先に lp-design-tokens スキルで整備する
3. references のコードを CSS ファイルとして追加し（1 セクション = 1 ファイル）、HTML 例をコピーして画像パス・リンク先・alt を差し替える
4. 必要な幅・比率がプリセットに無い場合はモディファイアを追加する（ID 上書きは禁止）
5. 商品クレジットや周辺セクションが必要なら credit-list スキル / editorial-sections スキルを併用する

## 検品チェックリスト

- [ ] SP（375px）/ タブレット（768px）/ PC（1280px）の 3 幅で全ブロックの並び・余白が意図通り
- [ ] 768px 前後 ±1px でレイアウトが破綻しない（メディアクエリ境界値の混在が無い）
- [ ] 全画像に width / height 属性があり、読み込み中にレイアウトシフトしない
- [ ] CSS 内にブロック固有 ID によるレイアウト上書きが無い（アンカー用 ID は可）
- [ ] 縦横比が想定と異なる画像を入れてもブロックが崩れない（aspect-ratio / object-fit の指定を確認）
- [ ] ホバー演出が hover 対応環境でのみ発火する（@media (hover: hover) 等のガード）
