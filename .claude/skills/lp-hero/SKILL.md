# /lp-hero スキル

LP のヒーローセクションの演出を「変種の選択 → 該当リファレンスの適用 → イベント契約の接続」の順で導入するハブスキル。コードは全て references/ にあり、本ファイルは判断と手順のみを扱う。

## いつ使うか

- 新規 LP でヒーローの入場演出（画像ズーム・タイトル段階表示）を実装するとき
- ローディング（プリローダー）演出とヒーロー演出の連携順序を設計するとき
- ヒーローにスクロール追従（パララックス / ロゴのスクロールフェード）を付けるとき
- px 座標で組んだアートディレクション固定のヒーローを全ビューポートに収めたいとき

## 変種の判断基準

| ヒーローの構成 | 採用する変種 | 読むリファレンス |
| --- | --- | --- |
| 静止画 1 枚（PC/SP 出し分け含む）＋タイトル・サブコピー | Ken Burns 入場タイムライン | references/entrance-timeline.md |
| スライドショー（複数枚を自動切替） | 入場タイムライン＋カルーセル autoplay ゲート | references/entrance-timeline.md ＋ references/event-contract.md（カルーセル本体は swiper-hero-carousel スキルを併用） |
| スクロールに応じて画像・ロゴ・サブタイトルが追従／フェード | rAF ＋ LERP パララックス | references/parallax-raf.md |
| px 座標固定のアートボードをどの画面にも収めたい | アートボード scale フィット | references/canvas-scale.md |

併用ガイド:

- 入場タイムライン＋パララックスは併用可。ただし transform を書く対象要素を分けること（例: Ken Burns は `img`、パララックスはそのラッパー）。同一要素に GSAP と rAF ループの両方が transform を書くと上書き競合する。
- アートボード scale は幅・高さが px 固定の設計専用。レスポンシブ可変レイアウトのヒーローには使わない。
- ローディング演出の有無に関わらずイベント契約は維持する（無い場合は代替発火。references/event-contract.md 参照）。

イベント命名契約（標準。発火順に記載）:

1. `loading:overlay-fade-start` — ローディングオーバーレイのフェード開始（ヒーロー画像が見え始める瞬間。Ken Burns の先行起動トリガー）
2. `loading:complete` — ローディング完全終了。ヒーロー入場タイムラインの開始トリガー
3. `hero:animation-complete` — ヒーロー入場完了。カルーセル autoplay 等、後続演出の開始トリガー

詳細な発火・購読の実装は references/event-contract.md を読む。

## 導入手順

1. ヒーローの素材構成（画像枚数、タイトル / サブタイトル / キャプションの有無、ローディング演出の有無）を確認し、上の表で変種を決める
2. 該当リファレンスを読み、JS モジュールと CSS を配置する（1 セクション = 1 JS モジュール、init 関数を export し DOMContentLoaded から呼ぶ）
3. ローディング演出があるプロジェクトでは references/event-contract.md に従いイベントを接続する。無い場合も同契約を維持し、代替発火を入れる
4. `prefers-reduced-motion: reduce` では入場アニメをスキップし、最初から全要素を表示する
5. 未再生のまま PC ⇔ SP が切り替わった場合の rescue 処理を入れる（references/entrance-timeline.md 参照）
6. 入場完了時に `clearProps` で transform / filter / will-change を除去し、以降の CSS 制御（hover 等）と競合しないようにする

## 検品チェックリスト

- [ ] リロード時に FOUC（一瞬全表示 → 消える → アニメ開始）が出ない
- [ ] ローディング → ヒーロー入場 → カルーセル autoplay の順に連鎖する（イベント契約どおり）
- [ ] JS 無効環境・`prefers-reduced-motion: reduce` で全要素が静的に表示される（隠れたままにならない）
- [ ] 入場未再生のまま PC ⇔ SP を切り替えても要素が非表示のまま残らない（rescue 動作）
- [ ] 入場完了後、対象要素の inline transform / filter / will-change が除去されている
- [ ] パララックス採用時: iOS 実機でラバーバンド操作（上下端で引っ張る）をしても画像が拡大固定されない
- [ ] アートボード scale 採用時: 主要ブレークポイントと画面回転後にキャンバスが切れずに収まる
- [ ] コンソールに警告・エラーが出ない
