# /scroll-lock スキル

オーバーレイ表示中に背面ページのスクロールを止めるユーティリティを導入するスキル。コードは全て references/scroll-lock-module.md にあり、本ファイルは判断と手順のみを扱う。

## いつ使うか

- モーダル・ライトボックス・全画面ナビ・ドロワーを開いている間、背面を固定したいとき
- プリローダー表示中にユーザーのスクロール操作を封じたいとき
- 「iOS だけモーダルの裏がスクロールする」という報告が来たとき（`overflow: hidden` 単体では iOS Safari のタッチスクロールは止まらない。CSS 3 プロパティ + JS のイベント抑止の併用が必要）

## 変種の判断基準

| 状況 | 採用する変種（references/scroll-lock-module.md 内） |
| --- | --- |
| オーバーレイが同時に 1 つしか開かない（モーダル 1 種、プリローダー等） | 基本版（lockScroll / unlockScroll） |
| モーダルの上にさらにモーダル等、多重オーバーレイがあり得る | ref counter 版（後から開いた方を閉じても先のロックが残る） |
| ロング LP の途中でモーダルを開き、iOS で閉じた後にスクロール位置が飛ぶ | scroll position 保持版（`position: fixed` + 位置復元） |
| キーボードの矢印キー・Space でのスクロールも封じたい | keydown 拡張（アクセシビリティへの影響が大きいので必要な場合のみ） |

迷ったら基本版から始める。ref counter / position 保持は「その症状が出てから」で遅くない。

## 導入手順

1. 既存実装の確認: `document.body.style.overflow = "hidden"` 等の場当たり実装や、同じ意図の `.is-*` クラスが既に無いか探す（ある場合は統合する）
2. references/scroll-lock-module.md の JS を `utils/scroll-lock.js` として配置し、CSS を global.css（またはユーティリティ CSS）に追記する
3. body クラス名はデフォルト `is-scroll-locked`。プロジェクトの `.is-*` 命名規約に合わせて変更可
4. モーダル / プリローダー / メニューの開閉処理から `lockScroll()` / `unlockScroll()` を呼ぶ（組み込み例はリファレンス参照）
5. 上の表に該当する要件があれば、対応する変種に差し替える

## 検品チェックリスト

- [ ] オーバーレイ表示中、マウスホイール・スクロールバー操作で背面が動かない
- [ ] iOS 実機（またはエミュレーション）でタッチスクロールが止まる
- [ ] Android で overscroll の bounce が出ない
- [ ] オーバーレイを閉じると通常どおりスクロールできる（クラスとイベントリスナーが両方解除される）
- [ ] オーバーレイ内部のスクロール領域（長文モーダル等）は必要に応じてスクロールできる
- [ ] 多重オーバーレイがある構成では、内側を閉じても外側のロックが維持される（ref counter 版）
- [ ] iOS でモーダルを閉じた後にスクロール位置が飛ばない（position 保持版を使った場合）
- [ ] コンソールに警告・エラーが出ない
