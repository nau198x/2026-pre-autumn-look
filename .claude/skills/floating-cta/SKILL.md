# /floating-cta スキル

スクロール位置に応じて表示 / 非表示が切り替わる `position: fixed` の CTA ボタンを導入するスキル。コードは全て references/ にあり、本ファイルは判断と手順のみを扱う。

## いつ使うか

- LP の主要 CTA（オンラインストア・予約・一覧アンカー）を、スクロール中も常に押せる位置に置きたいとき
- ヒーロー（ファーストビュー）では CTA を隠しておき、本文に入ってから出したいとき
- フッターや EC バナー等、ページ終端の固定要素とフローティングボタンが重ならないようにしたいとき

## 変種の判断基準

| プロジェクトの状況 | 採用する変種 | 読むリファレンス |
| --- | --- | --- |
| GSAP + ScrollTrigger が既に導入済み（LP のスクロール演出で使用中） | ScrollTrigger 版 | references/gsap-scrolltrigger.md |
| GSAP を使っていない軽量静的ページ（依存を増やしたくない） | IntersectionObserver 版 | references/intersection-observer.md |

- 両変種で HTML / CSS / クラストグルの挙動は共通（references/css.md）。JS の判定部分だけが異なる
- **1 プロジェクト内で混在させない**。ScrollTrigger を使うプロジェクトでは表示トリガーを ScrollTrigger に一本化する（lazy 画像ロード時の `ScrollTrigger.refresh()` で発火位置が一括再計算される利点がある。IO と併用すると再計算タイミングがバラける）

表示 / 非表示トリガーの選び方:

- **表示開始**: ヒーロー直下の導入セクションを「完全に通過した」時点が定番（ScrollTrigger 版は `start: "bottom center"`、IO 版は「画面外かつ上方向に抜けた」判定）。ファーストビューで CTA が出ると視覚ノイズになるため、ヒーロー内では出さない
- **非表示**: フッター・EC バナー等の終端要素の「上端がビューポート下端に触れた」時点（`top bottom`）。終端に同種の大きな CTA がある場合、フローティングと二重に見えるのを防ぐ
- 表示と非表示は独立した 2 つの真偽値（通過済みか / 終端ゾーン内か）で管理し、AND で最終表示を決める。上方向スクロールの戻りでも正しく再計算される

null ガードが必須の理由:

- トリガー要素のセレクタは案件ごとに差し替えるため、リネームや構成変更で**要素が存在しなくなる事故が最も多い**
- ボタン要素・表示トリガーが無い場合は早期 return（機能ごと無効化）、非表示トリガーが無い場合はフェードアウトだけ省略して動作継続、と縮退を分ける。ガードが無いと ScrollTrigger 版は初期化時に警告・IO 版は TypeError でスクリプト全体が死ぬ

## 導入手順

1. ページのセクション構成を確認し、表示開始トリガーと非表示トリガーの要素（クラス）を決める
2. 変種を上の表で決め、該当リファレンスの JS モジュールを配置する（init 関数を export し、DOMContentLoaded から呼ぶ）
3. references/css.md の CSS を配置し、出現アニメ（blur-in / fade-in / slide-up）を 1 つ選んで該当行を有効化する
4. HTML の `.floating-cta` ブロックを `</body>` 直前に置き、リンク先・テキストを設定する（`target="_blank"` の場合は `rel="noopener"` を付ける）
5. 非表示中の `inert` 属性トグルが入っていることを確認する（キーボードフォーカス・スクリーンリーダー対策）

## 検品チェックリスト

- [ ] 表示開始トリガーのセクションを通過するとフェードインする
- [ ] 上へスクロールして戻ると再び非表示になる（onLeaveBack / IO の逆方向判定）
- [ ] フッター等の非表示トリガーに到達するとフェードアウトし、通り過ぎて戻ると再表示される
- [ ] 非表示中に Tab キーでボタンにフォーカスが当たらない（`inert` の確認）
- [ ] トリガー要素のセレクタを故意に間違えてもコンソールエラーが出ない（null ガードの確認）
- [ ] PC ホバーで反転等のエフェクトが効き、SP ではホバー様の見た目にならない
- [ ] `prefers-reduced-motion: reduce` で表示 / 非表示は機能したまま transition だけ無効化される
- [ ] z-index がヘッダー・モーダル等の他の固定要素と正しく重なる
- [ ] コンソールに警告・エラーが出ない
