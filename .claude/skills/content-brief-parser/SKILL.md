# コンテンツブリーフ変換

クライアントから支給されるブリーフ（どの画像にどの商品クレジットを付けるかの構成表）は、案件ごと・担当者ごとに書式がバラバラで、表記ゆれ（全角数字・スペース欠落・URL 記法の差・欠番）を含む。支給テキストから直接 HTML を書くと、このゆれがそのまま本番に混入する。このスキルは「**支給形式が何であれ、まず標準スキーマに正規化する**」を鉄則とし、正規化 → 画像リネーム対応表 → セクション HTML 生成 → 検品、の順に機械的に処理する。

## いつ使うか

- 商品クレジット表・画像構成表・ルック一覧などの支給資料を LP に反映するとき
- 支給画像（仮名のままのファイル）と HTML の対応付け・リネームが必要なとき
- 既存 LP のクレジットを新しい支給資料で更新・差し替えるとき

## 判断基準

- **直接変換の禁止。** 支給テキスト → HTML を一足飛びにやらない。必ず `references/brief-schema.md` の標準スキーマ（ブロック番号 → 画像キー 1..n → クレジット 1..n｛品名 / 価格 / URL｝）への正規化を挟む。中間成果物（正規化した表）を残すことで、検品と後日の差し替えが可能になる。
- **支給形式は代表 3 形式のどれかに当てはめて判別する**: (A) ブロック形式（`# Block N` ＋「画像」「クレジット N」見出し）、(B) 見出し＋行形式（`# article NN` / `# Look N` の下に「品名 価格 URL」行）、(C) リファレンス形式（主役商品マーカー付きの行形式）。判別とフィールドマッピングは `references/brief-schema.md` の規則に従う。どれにも当てはまらなければ、最も近い形式の規則を流用しつつ差分をスキーマに追記する。
- **表記のゆれは正規化の段階で吸収する**: 価格は「¥ ＋カンマ 3 桁区切り」に統一、全角数字・全角スペースは半角化、品名と価格の間のスペース欠落を補う、URL は `https?://` で機械抽出する。**価格の `¥`・カンマは有る前提にしない**（同一ファイル内で `¥19,800` と `23100` が混在する実例あり。記号はこちらで付ける）。
- **1 見出しが複数ブロックを束ねる形式に注意**: `# look1-block1, look1-block2` のようにカンマ区切りで並ぶ場合、同一クレジットセットを列挙された全ブロックへ適用する（同じ着装を複数カットで見せているため）。見出しを分解して ID ごとにレコードを作る。
- **URL の無い商品（店舗限定等）はリンク無しのテキストとして残す。** 勝手に検索して URL を補わない。
- **画像は支給ファイル名のまま使わない。** 仮名（アンダースコア接頭辞・ゼロ埋めなし等）→ 正規名（ゼロ埋め 2 桁）のリネーム対応表を **HTML を書く前に**作る（`references/image-renaming.md`）。
- **不明・矛盾は推測で埋めない。** ブロック数と画像数が合わない、価格が欠落している、番号が飛んでいる（欠番が意図か脱落か不明）等は、質問リストにまとめてクライアント確認に回す。

## 手順

1. **形式判別** — 支給資料を `references/brief-schema.md` の 3 形式サンプルと照合し、形式とゆれ（全角・欠番・マーカー等）をメモする。
2. **正規化** — 標準スキーマの中間表に全ブロックを書き起こす。この時点で価格表記・数字の半角化・URL 抽出を済ませる。ゆれの吸収規則は `brief-schema.md` のパース規則に従う。
3. **画像リネーム対応表の作成** — 支給ファイル名 → 正規名の対応表を作り、リネームを実行する（`references/image-renaming.md` のテンプレートと手順）。
4. **セクション HTML 生成** — 正規化済みスキーマから `references/conversion-workflow.md` のテンプレートでブロックごとの HTML を生成し、所定の挿入位置に追加する。
5. **検品** — 下記チェックリストを消化する。突合（ブロック数・画像数・クレジット数）と URL 疎通は必ずコマンドで機械的に行う（手順は `conversion-workflow.md` 末尾）。

## 検品チェックリスト

- [ ] ブロック数が支給ブリーフと一致している（欠番は「意図的」と確認済みか、質問リスト行きになっている）
- [ ] 各ブロックの画像数・クレジット数がスキーマと HTML で一致している
- [ ] カタログ等のフラットな一覧セクションで、**クレジット行数と画像枚数が一致**している（並び順で 1:1 対応させるため、1 行でもズレると全体が 1 つずつ後ろへずれる。重複品番が紛れて行数が多いケースの実例あり）
- [ ] 価格がすべて「¥ ＋カンマ 3 桁区切り」（例: ¥00,000）になっている（カンマ無し・全角 ¥ の混入なし）
- [ ] 全角数字・全角スペースが残っていない（支給資料の見出し番号に全角数字が混ざる実例あり）
- [ ] 商品 URL がすべて疎通する（curl で 200 系を確認。リンク切れ・タイポの検出）
- [ ] URL 無し商品（店舗限定等）がリンク無しテキストとして正しく処理されている（空 href・ダミーリンクが無い）
- [ ] 主役商品マーカー（`(*)` 等）の意味をクライアントに確認し、表示仕様に反映済み
- [ ] リネーム後の画像ファイルが対応表どおりに全部存在し、支給仮名のファイルが残っていない
- [ ] 画像の `alt` とブロック番号表示（ゼロ埋め 2 桁）が正規名と揃っている
- [ ] 外部リンクに `target="_blank" rel="noopener"` が付いている
