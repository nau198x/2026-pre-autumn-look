# grayscale-color-reveal

グレースケール→カラーの 2 段階リビールを導入するスキル。基本形は「同一画像を grayscale 層と color 層の 2 枚重ねにし、GSAP で時間差リビールする」構造。層構造の HTML + CSS は references/css-layers.md、GSAP コードは references/js-wipe.md、1 層で済む行 stagger 変種は references/row-stagger-variant.md にある。

## いつ使うか

- ファッション・ルックブック系 LP で、画像の登場に「色がつく瞬間」の演出を入れたいとき
- ヒーローの初回表示を単純フェードより強い印象にしたいとき
- フォトブロックが多数並ぶページで、統一感のある画像入場演出を一括適用したいとき

## 実装方式の判断基準

| 方式 | 動き | 使う条件 | 参照 |
|---|---|---|---|
| ワイプ（標準） | 幕が開くように左→右スライドでグレー→カラーが順に現れる | 演出をしっかり見せたい / ヒーローや大判画像 | references/css-layers.md + references/js-wipe.md |
| クロスフェード | グレーがフェードイン→カラーが上からフェードで重なる | フォトブロックが多く、毎回ワイプだとくどい / 落ち着いた誌面調 | 同上（js-wipe.md 内のクロスフェード型タイムライン） |
| 行 stagger（1 層） | 行単位で opacity フェード + グレーのマスクが上→下に退いて色が現れる | 同一行に複数枚が並ぶグリッド / img を 2 枚重ねにしたくない（DOM・転送量の節約） | references/row-stagger-variant.md |

### ワイプ vs クロスフェードの選び分け

- **ワイプ**は移動量が大きく「発火の瞬間を目撃させる」演出。ヒーロー・章扉など 1 画面 1 枚級の画像に向く
- **クロスフェード**は本文中に何十枚も並ぶフォトブロック向け。全部ワイプにすると視線誘導がうるさくなる
- 同一ページ内での併用は可（ヒーロー = ワイプ、本文 = クロスフェード が定番構成）

### hero 用 vs 本文フォトブロック用

- **hero**: ページロード（またはプリローダー完了）をトリガーに 1 回だけ自動再生。ScrollTrigger 不要
- **本文フォトブロック**: ScrollTrigger で発火。ブロック数が多い場合は要素ごとに個別トリガーを作らず `ScrollTrigger.batch()` でまとめる（同時に視界に入った複数ブロックを 1 回のコールバックで処理でき、トリガー数も減る）

### batch の「追いつき処理」が必要な理由

タイムラインを paused で事前構築して batch で play する方式は、**初期化時点で既にビューポート内にある要素に batch の onEnter が走らないことがある**（特に SP は 1 画面の要素占有率が高く、ページロード時点で 1〜2 ブロック目が視界内に入っている）。そのため初期化直後に「既に視界内にある未再生タイムラインを即 play する」追いつき処理を必ず入れる。references/js-wipe.md の完全コードに含まれている。

## 設計上の必須事項

- **同一画像の 2 層構造**（ワイプ / クロスフェード）: grayscale 層と color 層は同じ src を参照する。ブラウザは同一 URL を 1 回しか取得しないので転送量は倍にならない
- **グレーの作り方は CSS フィルタ**: グレー版画像を別途書き出さない。`filter: grayscale()` + コントラスト調整 + `::after` のカラーオーバーレイ（{{ACCENT_COLOR}}）で作る。色調整がコード 1 行で済む
- **初期非表示は autoAlpha（visibility）系**: 層は CSS で `visibility: hidden` にしておき、GSAP の `autoAlpha` で出す。opacity だけだと非表示中もリンクがクリックできてしまう
- **reduced-motion / JS 無効対応**: 初期非表示 CSS は `@media (scripting: enabled) and (prefers-reduced-motion: no-preference)` でガードし、該当環境ではカラー画像が最初から見える状態にする
- **once 動作**: 全方式とも 1 回再生したら終わり。逆スクロールでグレーに戻さない

## 導入手順

1. 上の判断表で方式を決める。行 stagger の場合は references/row-stagger-variant.md のみで完結する
2. ワイプ / クロスフェードの場合、references/css-layers.md を読み、対象画像を 2 層構造の HTML に組み替え、CSS を追加する。カラーオーバーレイの色（{{ACCENT_COLOR}}）はブランドのアクセントカラーに置き換える
3. references/js-wipe.md のコードを animations.js（相当）に追加。hero は ロード完了（プリローダー併用時はその完了イベント）から、フォトブロックは DOMContentLoaded 後の初期化から呼ぶ
4. フォトブロックが多い場合は batch 版を使い、追いつき処理まで含めてコピーする
5. lazy 画像が多いページでは scrolltrigger-drift-fix スキルの refresh 対策を併用する

## 検品チェックリスト

- [ ] JS 無効・`prefers-reduced-motion: reduce` でカラー画像が最初から表示される（グレーのまま止まらない / 真っ白にならない）
- [ ] SP でページロード直後、ファーストビュー内のフォトブロックが再生される（追いつき処理の確認。リロードを数回試す）
- [ ] 最下部までスクロールして未発火のブロックがない
- [ ] 逆スクロールでグレーに戻らない
- [ ] 非表示状態の層の上でリンクがクリックできてしまわない（visibility 制御の確認）
- [ ] グレー層のトーン（コントラスト・オーバーレイ色）が PC / SP 両方で意図どおり
- [ ] 同一 src の 2 枚が二重リクエストになっていない（DevTools Network で確認）
- [ ] Safari で backdrop-filter 変種（行 stagger）が効いている（`-webkit-` プレフィックス）
